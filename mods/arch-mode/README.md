# arch-mode — Режим сборки архитектуры

Переключатель режимов работы агента. В режиме **«Архитектура»** перед каждым
вашим запросом автоматически подставляется инструкция «сначала карта, потом
стройка»:

1. Агент создаёт `.arch/<задача>/` с тремя файлами:
   - `overview.md` — из каких компонентов состоит решение, кто за что
     отвечает, как текут данные, что трогаем/не трогаем;
   - `contracts.md` — контракты между частями: интерфейсы, сигнатуры,
     схемы данных — всё, что связывает компоненты, **до** написания кода;
   - `build-plan.md` — последовательность небольших проверяемых шагов
     (скелет и заглушки → наполнение → интеграция), у каждого шага критерий
     проверки.
2. Неоднозначности — уточняющими вопросами до кода.
3. **Код запрещён**, пока вы явно не напишете «Собирай».
4. После одобрения режим сам переключается на «Код»: сборка строго по
   `build-plan.md` с отметками `[x]`; всплывшее неучтённое = обновить
   архитектуру и переспросить, а не импровизировать.

## Управление

| Действие | Как |
|---|---|
| Переключить Архитектура ↔ Код | Пилюля «Архит./Код» справа над полем ввода или `Ctrl+Alt+P` |
| Изменить шаблон инструкции | `Ctrl+Alt+Shift+P` (пустой ввод = вернуть стандартный) |
| Одобрить архитектуру | Напишите «Собирай» (или «Архитектура одобрена», «Одобряю», «go ahead») |

Шаблон хранится в `localStorage.agy_arch_template`, место запроса — `%TEXT%`.

## Отображение в чате

Инструкция остаётся в сообщении (агент её выполняет), но визуально сворачивается
в компактную пилюлю «Инструкция сборки архитектуры отправлена» — клик разворачивает.

## Технические детали

- перехват Enter — фаза `capture` на `window` (раньше обработчиков приложения);
- вставка в contenteditable — цепочка стратегий (paste → execCommand →
  beforeinput → DOM) с асинхронной проверкой результата, чтобы React-редактор
  не получил дубль;
- после успешной вставки отправка повторяется с флагом `suppress`;
- отладка: строки `pm-debug` в `C:\Users\ttt79\.antigravity-mods\crash.log`.
